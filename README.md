# USD/JPYを題材にした機械学習と仮想売買の検証

**過去の価格から売買の判断を作り、その判断を新しい市場データでも同じように実行できるかを検証するプロジェクトです。**

データの品質確認、モデルの比較、取引計算の再現、実際の価格データの受信までを段階的に記録しています。

## 現在どこまで進んでいるか

保存された検証では、**仕様を固定した41特徴量のモデルで、過去300取引の再現が一致しました。市場データAPIにも接続でき、次の新しい確定足を待つ段階です。**

| 段階 | 保存記録で確認できたこと |
|---|---|
| データを点検する | 価格系列の混在を調査し、年別CSVから265,905行を再構築 |
| モデルを選ぶ | 再構築データで比較し、相場状態の情報を加えた41特徴量を採用候補に固定 |
| 計算を揃える | 過去300取引の時刻・価格・コストを再現し、損益の差0を確認 |
| 新しい価格を受け取る | APIから100本取得、確定済み99本を検査。過去足を仮想売買へ投入せず待機 |
| これから確認する | 新しい足の初回処理、継続的な仮想売買、再起動・通信障害への対応 |

最新の処理件数は0件です。上記の300取引は過去データの再現であり、将来データによる取引実績ではありません。
実際の資金を使う注文は、この保存記録の対象ではありません。

## どのような仕組みか

米ドル／円の15分ごとの価格から、直近の値動きや相場状態を数値化します。
モデルの予測スコアで取引を選び、量を決め、30分保有した後の損益を費用込みで計算します。

```mermaid
flowchart LR
    A[市場の価格データ] --> B[確定した15分足を検査]
    B --> C[正規の価格履歴へ追加]
    C --> D[固定モデルで判断]
    D --> E[仮想売買と費用計算]
    E --> F[判断・取引・状態を保存]
```

APIは、外部サービスから価格データを受け取るための窓口です。今回のTwelve Data接続は価格取得用で、実注文を出す接続とは異なります。

## 今回の重要な学び

**良い成績が出たときこそ、データと計算の根拠を確かめることを重視しました。**

前回の非常に高い成績を調べたところ、異なる価格系列の混在が疑われました。
時刻を揃えるだけでは解消せず、元の年別データから作り直し、モデルを再評価しました。
以前の高い数字は履歴として残し、現在の成果を表す数字には使っていません。

また、短く切り取った価格履歴と全履歴では、微小な丸め差が一部の特徴量の値を変える問題も見つかりました。
正規の全履歴を使う方式に揃え、選んだ418時点で差0を確認しています。

## 再構築データでの比較

以下は2020–2025年の保存結果です。利益と損失の比率（PF）は1を超えると利益合計が損失合計を上回ります。

| 指標 | 基本モデル・30特徴 | 採用候補・41特徴 |
|---|---:|---:|
| 取引数 | 1,556 | 1,391 |
| PF | 1.686 | 1.734 |
| 最大下落率（決済時点） | −2.17% | −1.10% |

採用候補はPFと下落率で良い値を示しましたが、すべての指標で優れるわけではありません。
元Notebookの保存結果であり、今回の整理で独立に再実行した成績ではありません。2026年も研究で参照済みのため、将来の新しいデータでの確認を続けます。
