## 入力から取引まで

1. UTCの15分足OHLCを受け取る。セル58はNotebook内の `bars` に依存する。
2. BASEの30特徴と、追加後の重複を除いた50特徴を別々に評価する。Regime一覧11・Volatility一覧13のうち既存特徴との重複があるため単純合計54ではない。
3. 足tの確定後に判断し、次足Openで入り、その次の足Closeで決済する。保有時間30分。連続する15分足のみラベル化する。
4. HistGradientBoostingClassifierで上昇確率を学習する。
5. 過去年の時系列OOF予測で校正器を学習し、前年ValidationのBrier scoreでRAW / Platt / Isotonicを選ぶ。
6. 同じValidationでConfidence閾値と時間帯を選ぶ。最低40取引、平均純損益×sqrt(取引数)が主スコア。
7. ValidationでFIXED / GENTLE / MODERATE / STRONGを比較し、条件を満たすSizingを選ぶ。平均取引量の補正係数もここで固定する。
8. Test前の全履歴でモデルと校正器を再学習し、固定した選択内容で翌年を評価する。

## 今回の整理で確認した限界

- **データ集約の意味**：セル57は15分枠でfirst/max/min/lastを取る。枠内に5分足が1本しかなくても足を作れる。元の15分足と5分足が混在する場合、グリッドが整っても価格・区間の整合性は証明できない。
- **自動入力選択**：セル52は間隔の中央値を使い、混在した275,704行を15分足と判定していた。最新の266,510行の出力と、修復前の結果を混ぜて比較しない。
- **サンプルの一致**：`prepare_dataset` は各特徴一覧ごとに欠損を除外する。BASEと拡張候補の評価行が完全に同一かを別途確認する必要がある。
- **校正のフォールバック**：OOFが500件未満ならRAW、Isotonicは1000件未満ならRAWに戻る。表示上の選択名だけでは実際の校正器を識別できない場合がある。
- **同じValidationの反復使用**：校正・閾値・時間帯・Sizingを同じ前年で選ぶ。Testへの直接混入を避けても、選択候補数による過適合は残る。
- **2026の扱い**：複数のモデル・特徴量比較で既に結果を見ている。コードのCONFIRMATIONという名前を未使用データの保証とみなさない。
- **高PFの監査**：2022・2025の取引明細は添付のテキスト出力だけでは検査できない。高利益取引の出所、価格の連続性、集約処理、Sizing前後を照合する。
- **実行と入力検査**：元セルはnaive時刻をUTC化し、重複や欠損を削除する。自動修復を正しいデータ取得の代わりにしない。warningsの一括抑制も研究履歴に残っている。
