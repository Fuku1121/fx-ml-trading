# 研究の概要

## 何のための研究か

米ドル／円の価格データを題材に、機械学習による判断をどのように評価し、改善していくかを研究しています。
「価格が上がるかを当てる」ことに加え、取引にかかる費用を引いた後の損益や、悪い時期の下落幅も調べています。

## どのように進めたか

最初は値動きの方向を予測し、その後、取引を見送る条件や時間帯、決済方法、取引量を順に比較しました。
現在は、複数の決定木を組み合わせるHGBというモデルを使い、入力する情報の種類による違いを調べています。
試行錯誤は27段階のコードと研究報告に残しています。

検証では、データを時系列に沿って「学習」「設定を選ぶ期間」「評価する期間」に分けます。
例えば2020年を評価する場合、2020年の結果を使って取引条件を選ばない設計にしています。
ただし、同じ期間の結果を研究中に何度も見ているため、最後は新しい期間で確認する必要があります。

## 今回分かったこと

基本モデルに情報を追加した候補は、最新の比較では平均純損益などで基本モデルを上回りませんでした。
「入力する情報を増やすこと」自体を改善とは考えず、実験結果から採用を判断することが重要だと分かります。

同時に、一部の年には非常に高い成績があり、価格データには異なる時間足が混在した履歴もあります。
これらを監査してから、モデルの良し悪しを改めて判断する方針です。保存された数値だけで実運用の有効性を結論付けていません。

## このリポジトリで確認できる取り組み

| 観点 | 確認できる内容 |
|---|---|
| 課題設定 | 予測精度と取引損益を分け、何を改善したいかを定めていること |
| データ処理 | 時刻、欠測、重複、特徴量、将来の正解が判明する時刻を扱っていること |
| 比較と判断 | 改善しない方法も記録し、追加実験へつなげていること |
| 実装の整理 | 最新コードを役割ごとに分け、関数の説明と実行手順を備えていること |
| 品質確認 | 元コードとの一致、未来情報の混入、時間境界、取引の重複などをテストしていること |

実装済みなのは研究と検証のためのコードです。注文送信や運用時の障害復旧を含む取引システムは、まだ完成していません。
