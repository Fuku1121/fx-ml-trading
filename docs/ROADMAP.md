# 検証と改善の計画

見栄えの改善と、実測が必要な改善を分けます。文書の追加だけで収益性や運転実績が向上したとは扱いません。以下は今後の完了条件であり、実施済みチェックリストではありません。

| 優先度 | 課題 | 完了を判断する証拠 | 現在 |
|---|---|---|---|
| 高 | 運転異常を見逃さない | 心拍停止・HALTED・容量不足を外部へ通知し、テスト通知の到達を確認 | 外部通知未設定 |
| 高 | サーバー消失に備える | 暗号化した外部バックアップから別環境へ復元し、状態・履歴・重複防止を確認 | 自動外部バックアップ未設定 |
| 高 | 共通期間の実測を得る | 開始・終了時刻と停止履歴を確定し、2口座の費用込み成績を同じ範囲で集計 | 履歴準備から開始 |
| 中 | 予測と損益を区別する | 判断時点に対応する将来ラベル、確率帯ごとの校正、単純基準との比較を追加 | 一部の小標本監査のみ |
| 中 | 探索による過大評価を抑える | 条件固定後の追加期間、複数相場局面、依存性を考慮した不確実性を報告 | 未完了 |
| 中 | 第三者が研究を再実行できる範囲を広げる | 入力の取得条件・利用条件・バージョン・ハッシュ・コマンドを一貫して整理し、別環境で確認 | テスト・合成デモは可能、全学習の完全再現は未完了 |
| 中 | コードを継続的に保守しやすくする | 研究コードと運用コードのパッケージ境界、型、形式、入力検査を整理し、差分テストで確認 | 参照コードは配置時の形を保持 |
| 後 | 実約定への近さを調べる | 観測価格と約定可能なbid/ask、遅延、業者の取引条件の差を測定 | 仮想価格・費用仮定のみ |

実行中の比較のモデルやしきい値は、この改善計画を理由に変更しません。研究上の変更は別バージョンで検証します。実資金の注文への移行は、この計画の完了や1か月の利益だけで自動的に決まるものではありません。

## 運転中の確認

現状は外部通知がないため、少なくとも日次でサービス、心拍、4通貨の受信時刻、phase、ディスク、停止理由を確認する必要があります。週末の休場と市場時間中の無受信は分けて判断します。これは推奨する運用手順で、日次の自動監視が設定済みという意味ではありません。

WARMUPから比較に移ったときに保存される開始・終了時刻を確認します。HALTEDや準備期限切れの場合は原因調査が必要で、ただ30日待っても完全な比較結果にはなりません。既存状態を初期化して停止を隠さないでください。
